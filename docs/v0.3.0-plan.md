## Problem Statement

v0.2.0 uses `auth.loader` custom `fetch()` hooks for both `google` and `google-vertex`
providers. This works for `google` but **fails for `google-vertex`** because OpenCode's
`Provider.getSDK()` explicitly deletes `options.fetch` for the native Vertex AI SDK:

```typescript
// packages/opencode/src/provider/index.ts — getSDK()
if (model.providerID === "google-vertex" && !model.api.npm.includes("@ai-sdk/openai-compatible")) {
  delete options.fetch
}
```

After deletion, the timeout wrapper falls through to `customFetch ?? fetch` where
`customFetch` is `undefined` — so the unpatched `globalThis.fetch` is used instead.
The auth hook's custom fetch never reaches the AI SDK for google-vertex.

### Investigated Alternatives

| Approach | Verdict |
|----------|---------|
| `experimental.chat.messages.transform` | Cannot work — `differentModel` stripping in `toModelMessages()` removes metadata from cross-model messages, and the hook doesn't know the target model |
| `chat.params` | Cannot work — output is `{ temperature, topP, topK, options }`, messages are not exposed |
| `globalThis.fetch` monkey-patch | Works — the only interception point that survives OpenCode's `delete options.fetch` |

## Architecture: Global Fetch Interceptor

Replace `globalThis.fetch` at plugin load time with a thin wrapper that:
1. Checks the URL — only intercept Gemini `generateContent`/`streamGenerateContent` endpoints
2. Parses the JSON body
3. Runs `fixThoughtSignatures()` (same proven function from v0.2.0)
4. Serializes and forwards to the original `fetch`

```
Plugin loads → replaces globalThis.fetch
                     │
                     ▼
              Any fetch call
                     │
                URL filter:
        generativelanguage.googleapis.com
        OR aiplatform.googleapis.com
        + generateContent / streamGenerateContent
                     │
          ┌──────────┴──────────┐
          │ NO                  │ YES
          │ pass to original    │ parse body JSON
          │                     │ fixThoughtSignatures()
          └─────────────────────│ stringify
                                │ pass to original
                                └──────────────────
```

### Why This Is Safe

- **Bun's fetch is writable**: `Object.getOwnPropertyDescriptor(globalThis, 'fetch')` →
  `{ writable: true, configurable: true }`
- **Late-binding**: The AI SDK's `getOriginalFetch` is a thunk `() => globalThis.fetch` —
  evaluated at call time, not import time. A patch installed at plugin load is picked up.
- **GoogleAuth unaffected**: `@ai-sdk/google-vertex` uses `generateAuthToken()` →
  `GoogleAuth` → `gaxios` → `node-fetch` for auth token HTTP calls. `node-fetch` is NOT
  `globalThis.fetch` in Bun, so auth flows are never intercepted.
- **MCP unaffected**: MCP transports use `this._fetch ?? fetch` — their URLs don't match
  the Gemini filter.
- **Other providers unaffected**: Anthropic, OpenAI, etc. — URL filter skips them.
- **Bun internals unaffected**: Module loading, npm resolution use internal C++ networking,
  not the JS-level `fetch`.
- **Chain-safe**: We capture `originalFetch` at patch time. If another plugin also patches,
  the chain works — each wrapper calls the one it captured.

### Performance Impact

| Request type | Overhead |
|---|---|
| Non-Google URL | 1 function call + `url.includes()` check (~0.001ms) |
| Google non-generate | 2 `includes()` checks (~0.001ms) |
| Gemini generateContent | `JSON.parse` + tree walk + `JSON.stringify` (~1-5ms on large bodies) |

The JSON overhead only applies to matching Gemini requests, which take 1-30 seconds anyway.

### installFetchInterceptor() Design

```typescript
export function installFetchInterceptor(): () => void {
  const originalFetch = globalThis.fetch

  // Guard: already patched
  if ((originalFetch as any).__thought_sig_patched) {
    return () => {}
  }

  const patched = async function patchedFetch(
    input: RequestInfo | URL,
    init?: RequestInit,
  ): Promise<Response> {
    if (!isGeminiGenerateContentRequest(input)) {
      return originalFetch(input, init)
    }
    if (!init?.body || typeof init.body !== "string") {
      return originalFetch(input, init)
    }
    let body: Record<string, unknown>
    try {
      body = JSON.parse(init.body)
    } catch {
      return originalFetch(input, init)
    }
    fixThoughtSignatures(body)
    return originalFetch(input, { ...init, body: JSON.stringify(body) })
  }

  ;(patched as any).__thought_sig_patched = true
  globalThis.fetch = patched

  // Return uninstall function (useful for tests)
  return () => { globalThis.fetch = originalFetch }
}
```

Key details:
- Captures `originalFetch` at install time (chain-safe)
- Sentinel `__thought_sig_patched` prevents double-install
- Returns uninstall function for test cleanup
- Same URL matching and body parsing as v0.2.0's `createPatchedFetch()`

### Plugin Export Design

```typescript
export const GeminiThoughtSignatureFix: Plugin = async (_ctx) => {
  installFetchInterceptor()
  return {}
}
export default GeminiThoughtSignatureFix
```

Single export. No auth hooks. No provider targeting. The fetch interceptor works
globally regardless of which provider makes the request.

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Future OpenCode captures fetch at load time | Low | AI SDK uses lazy thunks; would require major refactor |
| Another plugin also patches fetch | Low | Chain-safe — we capture original at install time |
| JSON.parse fails on a valid request | Very Low | try/catch passes through on failure |
| `experimental` hook for messages could be added later | Low | Fetch interceptor is more reliable anyway |
| Bun update changes fetch descriptor | Very Low | `writable: true` is a standard property; breaking this would break the ecosystem |

## Rollback Plan

If v0.3.0 causes issues, the shim's auto-update mechanism means reverting to v0.2.0
requires only pushing a reverted `dist/index.js` to GitHub. The shim will pick it up
within 24h, or immediately if the cache is cleared.
